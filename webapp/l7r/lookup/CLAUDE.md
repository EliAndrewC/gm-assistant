# `l7r.lookup` - the `/look-up` Discord command (feature 218)

A player types `/look-up what are our minions called?` in the GM's Discord and gets a short answer
that only they can see. A cheap Gemini model answers from a glossary Claude wrote, the Wasp
campaign brief, and the asker's own character. Spec, research and evaluation results:
`specs/218-lookup-command/`.

| file | holds |
|---|---|
| `glossary.jsonl` | The glossary: one entry per line (term, aliases, kind, scope, reading, meaning, summary, related, link, source). **Claude-written data** - see "Refreshing the glossary". |
| `glossary.py` | Load and validate it (bad lines name their line number), merge in the baked people entries, render it as compact prompt text. Holds the in/out rule. |
| `reviewed.json` | Which source sections (of `l7r.md` and `rules/*.md`) a session has read, with a hash of their text then. |
| `sources.py` | Splits the sources into heading sections; `stale` lists what changed since review, `mark` records a review. |
| `campaign.py` | The model's instructions and the Wasp campaign brief; assembles the prompt in cache-friendly order. |
| `profiles.py` | Who is asking: sheet-app ownership to profile, clan of origin from the school, hourly refresh from the public sheet page. |
| `links.py` | The roster, the mechanical name linker, and the filter that strips any address the glossary or roster does not vouch for. |
| `gemini.py` | The Gemini REST call (no SDK - see the docstring), per-model thinking settings, usage to cost. |
| `ledger.py` | The daily spending ceiling and the local query log. |
| `service.py` | `Lookup.answer()`: the whole path, used by the bot AND the evaluation, so they cannot drift. |
| `bake.py` | Builds `data/roster.json`, `data/profiles.json` and `data/people.jsonl` (needs OP + sheet credentials; runs locally, never on the box). |
| `eval/` | The efficacy experiment: `questions.jsonl` and the runner. |
| `data/` | Gitignored: the baked data, plus `spend.json` and `log.jsonl` on the box. |

The Discord side lives in `l7r/mention/` (`gateway.py` for the interaction calls, `responder.py`
for `answer_interaction`), because the command arrives over the mention responder's gateway
connection: the application has no interactions URL, so slash commands come as
`INTERACTION_CREATE` events and no web server is needed.

## The glossary's in/out rule (GM 2026-10-17)

In: anything a player might need to name or recognize - "the Ministry of Retainers should be
something in the glossary". Out: hyper-specific numbers and procedures, "the budget of a county
magistrate should not, even if the term county magistrate is". A judgment call, not a test.

Every entry carries a scope: `wasp` and `world` are what a Wasp player is asking about; other
campaigns' material (`karmic-inquisitors`, `hidden-way`, ...) stays in, tagged, because the GM
ruled `l7r.md` is not out of bounds. Obsidian Portal GM-only fields and records are never a source.

## Refreshing the glossary

The glossary is Claude-written, not generated by Gemini (the GM's call). To refresh after the GM
edits `l7r.md` or the rules:

```
( cd webapp && python3 -m l7r.lookup.sources stale )     # lists changed or new sections
```

Read each listed section, add or correct glossary entries for anything a player might need to name
(append JSON lines; `term`+`scope` must be unique; `source.section` is the heading path the
`stale` list printed), then record the review:

```
( cd webapp && python3 -m l7r.lookup.sources mark setting/l7r.md "L7R Campaign Notes > The Wasp" )
```

`mark FILE [HEADING-PREFIX]` marks every matching section, so a prefix covers a whole chapter.
People need no refresh: every public Obsidian Portal character is baked into `data/people.jsonl`
from its tagline and tags at each deploy, and a hand-written entry of the same name wins.

## Deploying

```
eval "$(./scripts/lightsail_access.py --export)"
./scripts/deploy_mention_bot.sh "$LIGHTSAIL_TARGET"      # bakes, ships, restarts
./scripts/register_lookup_command.py                     # once, or after changing the command
```

The box gets `[lookup] gemini_api_key` from the secrets file **and never `[gemini] api_key`**,
which also pays for portraits and backstories. Without the dedicated key the bot runs and
`/look-up` replies that it is not set up. The ledger and log on the box survive redeploys (rsync
excludes them).

The box runs **Python 3.12**, not this repository's 3.14. `pyproject.toml` pins `l7r/mention` and
`l7r/lookup` to py312 for ruff, and `tests/test_box_python.py` parses every shipped file with the
3.12 grammar - `ruff format` once wrote a 3.14-only `except A, B:` here.

## Choosing the model

`[lookup] model` in `development-defaults.ini`. Thinking settings per model in `[lookup_models]`,
prices in `[lookup_prices]` (both configuration because they differ by model and change). The
choice rule (spec, Story 7): the cheapest tier whose correctness is within 5 points of the best
measured, with no more invented answers on the unanswerable questions than the best tier.

## How to test

```
( cd webapp && python3 -m pytest -n auto tests/test_lookup_core.py tests/test_lookup_service.py tests/test_lookup_eval.py tests/test_lookup_discord.py tests/test_box_python.py )
( cd webapp && python3 -m l7r.lookup.eval --model gemini-3.1-flash-lite )   # live, about 10 cents
```

The evaluation writes `specs/218-lookup-command/eval/<model>-<date>.{json,md}`; the `.md` lists
every failing answer. Scoring is mechanical (required facts, required links, abstention), so after
a run read the failures and fix whichever is wrong - the glossary, the instructions, or the
question's grading. The questions were written by the same session that wrote the glossary, so
they flatter it; real questions from the query log (`data/log.jsonl` on the box) are better ones.

Live check in Discord: type `/look-up who is our boss?` in the GM's server; the reply should say
Tsuruchi Kyoma, link his page, and be marked "Only you can see this".
