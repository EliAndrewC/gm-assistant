# Key paths (full index)

*Project reference, moved out of [`../CLAUDE.md`](../CLAUDE.md) on 2026-10-17 so it is loaded on demand rather than in every session (and every subagent) context. CLAUDE.md keeps the one-line always-on version of each rule.*

**Load this file when:** you need to find where something lives: webapp routes, the REPL, the Discord bots, the OP crawler, issue watch, the screenshot/DOM-audit suite, the review agents, or how features are numbered.

---

**Key paths**:

- `.specify/memory/constitution.md` - the constitution
- `.specify/templates/plan-template.md` - Constitution Check gate lives here
- `/gm-assistant/webapp/` - **L7R Toolkit** (CherryPy + Jinja2). Run with `cherryd --import l7r.app` from this dir (`l7r` itself is a namespace portion with no code in it since feature 119 - the mount is a side effect of `l7r.app`). Routes: `/` landing, `/relics`, `/relics/<slug>`, `/names` (with `?gender=` / `?caste=` filters), `/places`, `/places/<slug>`, `/dreams` (dream-divination framework + example gallery, public `pool/` tier only), `/dreams/<slug>`, `/shrines` (feature 216: shrine builder - the player designs a remote, unstaffed shrine with no prices shown; a GM session also sees the cost ledger and Tadashi's per-contract Commerce haggling; index in [`webapp/l7r/shrines/CLAUDE.md`](../webapp/l7r/shrines/CLAUDE.md)), `/api/names` (feature 213: JSON name suggestions for the character-sheet app's generated NPCs - male, peasant or samurai-eligible, clear of the campaign's used names; bearer-token auth on `[character_sheet] names_token`, 503 when unset), `/chargen/*` (legacy chargen mounted as a sub-app). New code under `l7r/`, a **PEP 420 namespace portion** (no `__init__.py`; feature 119 made it one so the diagram engine's `l7r.diagram.*` could share the parent package - that engine is in its own repository since feature 131, so the only remaining reason is not to churn; `tests/test_namespace_portion.py` still guards it). Legacy chargen modules on Principle X grace period.
- `/gm-assistant/scripts/repl.py` - the GM's Python REPL (dice, exact XkY odds, `name()` / `place()` picks off the pools); works from the host (`podman exec` into the container) or inside it. Code and its index in [`webapp/l7r/repl/CLAUDE.md`](../webapp/l7r/repl/CLAUDE.md).
- `/gm-assistant/scripts/mention_bot.py` - the Discord mention responder (feature 203): one gateway connection listening, any number of bot tokens speaking, so the bot a player addresses is the bot that answers. Runs on the GM's always-on box, NOT on fly.io - the fly apps scale to zero and holding a socket open would mean paying for a full-time machine. Code and its index in [`webapp/l7r/mention/CLAUDE.md`](../webapp/l7r/mention/CLAUDE.md).
- `/gm-assistant/webapp/l7r/lookup/` - the **`/look-up` Discord command** (feature 218): a player asks a vague question privately and a cheap Gemini model answers from a Claude-written glossary (`glossary.jsonl`), the Wasp campaign brief and the asker's character from the sheet app; people in replies are linked mechanically. Runs inside the mention bot on the Lightsail box. Glossary refresh procedure, deploy and the evaluation in [`webapp/l7r/lookup/CLAUDE.md`](../webapp/l7r/lookup/CLAUDE.md).
- `/gm-assistant/webapp/l7r/money/` - the **`/money` skill's** arithmetic and data (feature 219): exact koku/bu/zeni/sen, PPP dollars from dated basket snapshots, "big deal" dollars from a dated wage, and the labeled price ledger; CLI `python3 -m l7r.money`. Research comes from the diagram repository by GitHub issue ([`.claude/skills/money/research.md`](../.claude/skills/money/research.md)). Index in [`webapp/l7r/money/CLAUDE.md`](../webapp/l7r/money/CLAUDE.md).
- `/gm-assistant/scripts/op_consent_census.py` - consent-first census of other people's L5R campaigns on Obsidian Portal (which owners allow bots); results stay gitignored. `scripts/op_fetch_campaigns.py` then caches and indexes the crawlable campaigns' public pages so a session can summarize and search them. Code and its index in [`webapp/l7r/opcrawl/CLAUDE.md`](../webapp/l7r/opcrawl/CLAUDE.md).
- `/gm-assistant/webapp/l7r/issuewatch.py` - **issue watch** (feature 215): sessions in different containers coordinate through a GitHub issue. Installed into the shared `~/.claude/hooks/` (`python3 webapp/l7r/issuewatch.py install`; `install --check` says whether the installed copy is current - re-run install after changing the module), it is silent unless a session in a repository with `.claude/issue-watch.json` runs `python3 ~/.claude/hooks/issue_watch.py start OWNER/REPO#N`; then new activity reaches the session at the GM's next message, blocks its turn end once, or wakes it when idle. `show` / `post` / `edit` (replace the description and post a notice, since watches see comments, not edits) / `close` / `open` / `status` / `stop`; issues may be named by URL. **"Please implement <issue URL>" means watch it until it is closed** - the procedure is "Working a GitHub issue" in the user-level `~/.claude/CLAUDE.md` (one copy, both containers). Design, GitLab notes and test steps in the module docstring and `specs/215-issue-watch/`.
- `/gm-assistant/webapp/Makefile` - `make done` runs ruff + format check + mypy --strict + pytest + 100% coverage gate
- `/gm-assistant/webapp/tests/screenshot.py` and `tests/dom_audit.py` - Playwright suite for Principle I verification at GM-100 / GM-200 / tablet / mobile. The screenshot script outputs multi-scroll contact sheets to `/tmp/l7r-shots/sheet-<page>-<viewport>.png`.
- `/gm-assistant/.claude/agents/frontend-review.md` - independent design-review subagent. Invoke before declaring a UI change done if the same agent implemented AND reviewed.
- `/gm-assistant/.claude/agents/mention-context-review.md` - independent audit of the Discord bots' scripted replies, asking of each whether it makes sense to somebody who does not already know what it refers to (GM 2026-08-31). Run it **one category-group at a time, never in parallel** - the GM's terminal has crashed on fan-out. Its findings and the standard live in [`webapp/l7r/mention/lore/CLAUDE.md`](../webapp/l7r/mention/lore/CLAUDE.md).
- `/gm-assistant/.claude/agents/shrine-text-review.md` - independent review of the shrine builder's player text, one wizard section per call, with a shared (cached) system prompt; how to run it in [`webapp/l7r/shrines/CLAUDE.md`](../webapp/l7r/shrines/CLAUDE.md) (feature 216).
- `/gm-assistant/.claude/agents/backstory-review.md` - independent review of synthesized NPC prose (`/synthesize`, `/chargen`), run automatically by those skills before the GM sees a backstory. Holds a **growing catalog of previously GM-caught mistakes** plus the baseline canon/style rules and sweeps them by enumeration, so recurring errors are fixed in-session. When the GM catches a new category of mistake in generated prose, distil it into a general rule here (follow the Subagent-check TDD procedure).
- `/gm-assistant/.claude/skills/relic/pool/` - exemplar of the pool data convention (Principle III)
- `/gm-assistant/.claude/skills/name/pool-male.jsonl` + `pool-female.jsonl` - the given-name pool consumed by the `/names` section and the chargen engine

**Since 2026-08-25 (feature 131) a feature is identified by REPOSITORY + number**: the diagram repository holds 005-131 (its features) and continues from 132; this repository holds 001-004 and 011 and restarts at **200**. Spec-kit features (the `specify` -> `plan` -> `tasks` -> `implement` flow) live under `specs/NNN-*/`. There is deliberately **no single "active plan" tracked here** - a hardcoded pointer just goes stale as features come and go. For current status, look at the highest-numbered `specs/` dir, its `tasks.md` checkboxes, and `git log`.
