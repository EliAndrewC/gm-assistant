## Message 1

Our Shrine Builder was a big hit with the players. However, there are two features that I think they would really like based on talking to them. The first is synthesizing a description of the shrine from the options that were selected. Now, I think that this is probably best done with an LLM call to our Gemini account that we already use in other places in the GM Assistant app. I think this should be relatively cheap, because I think that unlike the NPC backstory generator, which requires us to use an expensive model and also feed in basically almost all of our setting notes, I think this could be done much more easily with probably a combination of a cheaper model and also much less in the way of a long system prompt.

The other thing I think that we want is an art generator that shows the shrine. I think we could probably synthesize a good prompt without going through an LLM for that, since I think it would be mostly deterministic, though I'm not sure. And I don't mind going through an LLM to create a good prompt if we think that that will give us better results.

please make those changes and then deploy them to fly.io, and let me know if you have any questions about how this should work before we proceed.

Oh, actually, there is another thing that we should do as part of this, which is that every step along the way should have an optional "other" selection which if checked displays a freeform text box where people can enter their own thing. And then there should be a way to indicate whether or not this is something that is being done instead of the options that are selected already, or in addition to whatever is already selected. I don't have a great sense of what that UI should look like, but please make that happen and then incorporate both into both the LLM description and the image generation.

Also, because players have already created existing shrines, then we should add a requirement, not just for this feature, but for all future features on the Shrine Builder, to maintain backwards compatibility for existing shrines that have been constructed. For example, https://l7r-gm-assistant.fly.dev/shrines?shrine_name=The%20memorial%20hermitage%20of%20Shoda%20the%20Fox-forest%20Guardian&kind=memorial&heart=bones&preparation=washed&sharing=headmound&sharing=temple&resting=mound&display=sealed&form=himorogi&ground=moss&hall=open&altar=natural&box=bamboo&bell=suzu&gate_form=trees&path=earth&enclosure=none&guardians=foxes&lanterns=none&water=stream&plaque=patron&stele=board&rite=full#step-review is the shrine that Shizu created, and therefore that link must continue to work. That is not to say that the URL format must remain exactly the same, because, for example, we could have a compatibility layer where if the URL format changed in some way, then as long as those old links got transformed and then redirected into the correct format, then that would be fine. The requirement is that the old links continue to work, not that the format must remain the same, if that makes sense.

## Message 2 (answering: who may generate, art style, pricing Other, saving)

Yes, only signed in players and the GM should be able to trigger these builds. I think that players should be able to choose from different art styles based on their own preference and they should be able to generate new images if they don't like the previous ones, either by simply clicking the button again to do it again to see the new version, or selecting a different art style, etc. I think that for pricing the other entry, we can have an optional amount indicated where the default option is unpriced. And then when we are showing the price at the end, we would indicate that it is the price listed plus whatever these other unpriced options cost, if there are other options which are not priced. And if they are priced, then we simply add them to the cost in the normal way.

Now, as for saving the results, I do not want to save them to fly.io, but instead, I want there to be an option which allows players to create a wiki page on Obsidian Portal for this shrine. We can synthesize a description and then the player can edit the description. Prior to it being uploaded, and it can generate art and then make as many tries as they want until they like the result, and then when they click upload, then this will create the wiki page and save off both the description and the image, which will be integrated into the Obsidian Portal wiki page. And then the wiki page will also have a link back to this permlink for the shrine. And then any time, starting now, that someone visits this permalink, then we will check to see whether or not there is already a wiki page for this shrine. And then I guess we would separately need to check whether the currently selected options match what is on that wiki page. And if they do, then we simply have a link to the wiki page. And if they do not, then we link to the wiki page, but indicate that the current options differ, and that if you want to update the wiki page, then you will need to click the update button or whatever.

I suppose that if you visit the link, for the shrine, on the shrine builder, and there is already a wiki page, then we should also load the synthesized description and the image so that people can see what those current options are, but then give the player a chance to generate new ones, either by manually editing the prompt or synthesizing another description, or even editing the prompt that was used to generate the image and then generating a new image. Like if they want to specify some detail about the stone guardians that are carved or something, like the where they are placed or whatnot. In that way, I will be able to take Shizu's shrine that he created and then make a wiki page using this process, then link him to his own shrine by linking that back to him in a way that gives him the option to update it as per his preference and then update the wiki page.

How does that sound? Does that seem doable? Are you able to move forward with this, or is there more that we should talk about first?
