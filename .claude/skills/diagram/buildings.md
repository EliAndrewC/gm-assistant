# Mode A: Compound and building plans

**Research:** the historical basis for these rules - what was found, the decision it drove, and every disclosed departure - is in [`research/buildings.md`](research/buildings.md). Load it when you are CHANGING a rule or questioning one, not to follow it.

This file is the Mode A half of the /diagram skill: interior plan views of manors, magistracies, temples, keeps, and battlefields, hand-authored in SVG.  Read [`SKILL.md`](SKILL.md) first for everything shared (principles, workflow, labeling, style conventions, render pipeline, output convention); this file adds the Mode A building vocabulary, checklist, and historical grounding.  The canonical template is [`pool/magistracies/ochiba-magistracy.svg`](pool/magistracies/ochiba-magistracy.svg) - copy it as the starting point for a new compound plan and edit from there rather than rebuilding from scratch.

## Scale

Compound plans are drawn at **3 px = 1 ft** - the most-zoomed rung of the scale ladder in SKILL.md. Declare it on every sheet with a **scale bar**: a 90 px bar with end ticks and a midpoint tick, labeled `30 ft` with `(3 px = 1 ft)` beneath, placed on open parchment near the bottom of the sheet. Sanity-check every new feature in real feet before placing it - a 10×8 px room is a 3.3×2.7 ft closet, and a 300 px building is a 100 ft hall; both should be deliberate, not accidents.

**The ~2x point-glyph doctrine is RETIRED (GM ruling 2026-07-21): everything with a real footprint draws at TRUE size, point glyphs included** - at 3 px = 1 ft even a 3 ft kneeling mat is a visible 9 px, so Mode A never needs a size bump. Kneeling marks, the gate notice board, salt wards, fire-water tubs, hearth marks, and threshold stones were all re-drawn true-size on both pool manors the same day. The ONE sanctioned divergence is the **stroke convention** (same doctrine as Mode B, see SKILL.md "to scale"): linework floors (lattice-bar lines, dashed dividers, wall strokes at true thickness) and **location markers** for sub-glyph features - the WELLS, whose ~22 px curb glyph marks the well's to-scale location without claiming a real ~3-4 ft curb's pixels (GM-confirmed marker status 2026-07-21), and the SALT WARDS, whose r2.5 glyph (~1.7 ft) marks a morijio heap that is truly ~0.3-0.7 ft - sub-glyph at any render, so a marker, per the size-audit's re-derivation (do NOT call r2.5 'true size'). Two hard limits survive from the old doctrine's history (size-audit, 2026-07): **(1) a stroke floor is LINEAR (a line width), never an AREA license.** **(2) Buildings are not glyphs** - the cell, the tax kura, the granary, the kitchen, and even a deliberately grand shrine are audited at TRUE size, not waved through as "the X glyph." A note that a feature is an *intentional divergence* (a grand hall, the "Ochiba slot") fixes its DIRECTION, not its MAGNITUDE: "grand" still has a ceiling, re-derive it. A cautionary tale about tolerances: the template originally carried a "~27 ft main-gate opening" as a tolerated stretch, justified by "a Chinese county gate ran three bays" - but three bays describes the gate STRUCTURE; the actual passage is one bay, ~10-13 ft. The size-audit agent caught the laundering (2026-07); gates are now drawn at passage width (~40 px). A later run (2026-07) caught four more laundered sizes - a 53 ft kitchen, a 53 ft shrine hall, a 53 ft-wide stable, a 45 ft-deep granary, all propagated from this file's own vocabulary values below - which is why those values were re-derived and a **proportion/hierarchy sweep** added (see grounding). The residence-wing lengths (Ochiba ~200 ft, Hayakawa ~180 ft), by contrast, were AUDITED AND VALIDATED - chief-retainer-class main houses genuinely ran that long.

## Design notes and the review gate

Every Mode A diagram saves a **design-notes file** alongside its SVG/PNG: `pool/<subject>.notes.md`. It records what the SVG cannot: the intent. Sections: subject + program type; **knob settings** (every knob, even the ones left at default); the subject's particulars; **deliberate choices and tolerated stretches** (so a reviewer does not "fix" them); and a **Review log** of applied and overruled findings. Write it at design time, before the review - it is the reviewer's second source, letting it check intent-vs-execution instead of guessing.

Mode A's automated gate is a **subagent review**, not a scripted validator (a compound plan has far fewer objects than a settlement, and most failure modes are judgment calls a script can't encode). The author is not a reliable reviewer of their own plan, so before presenting a diagram as done:

1. Invoke the **`building-review`** subagent ([`/.claude/agents/building-review.md`](../../agents/building-review.md)) with the subject name. It reads this file's program + grounding, the notes file, the PNG, and the SVG, and returns errors / questionables / nitpicks / confirmations.
2. **Iterate**: fix valid findings and re-run, until the reviewer returns no findings OR the remaining findings are overruled by context it lacks (GM rulings, setting canon). Record every overrule with its rationale in the notes file's Review log - the reviewer reads the log and will not re-raise settled items.
3. One reviewer covers ALL building types - the type-specific knowledge lives in this file's "Compound programs" section, which the reviewer reads at review time. Adding a new building type means writing its program here, not a new agent.

**Tuning a check (the subagent-check TDD procedure - REQUIRED when a review misses a category).** When the GM (or a fresh accuracy pass) finds a problem the reviewers did not catch, do NOT just fix the map. Fix the CHECK first, in this order, so the category is caught forever after:

1. **Add a GENERAL rule** to the relevant agent (`building-review` for program/layout/circulation; `size-audit` for dimensions/proportion) - phrased for the whole category, with NO hint of the specific example ("a kitchen must not out-foot the family's quarters", not "the Ochiba kitchen is too big"). Promote it to a MANDATORY ENUMERATED OUTPUT SWEEP if it is the kind of thing that gets skimmed - loose prose in the method section gets skimmed; a required per-item sweep fires.
2. **Red-test it** against the still-unfixed map: run the tuned agent (via a general-purpose agent that Reads the edited definition, since the registered agent type is a stale snapshot mid-session) and confirm it now FLAGS the defect. If it doesn't, the rule isn't good enough yet - sharpen and repeat. Leave any laundering value in this file IN PLACE for this test, so you are proving the check catches the defect despite the doc that fooled it.
3. **Only now fix the map** (and correct whatever laundered value in this file drove it).
4. **Green-test**: re-run the tuned agents; the map should pass clean.
5. **Record the specific example** in the agent definition's "validated examples" note and in the design-notes Review log - a validated example is the negative-fixture equivalent for a judgment-call check (coverage/coincidence does not prove a check has teeth; a recorded red-then-green does).

This is the Mode A instance of the project-wide subagent-check TDD rule in [`/gm-assistant/CLAUDE.md`](../../../CLAUDE.md); it applies to both `building-review` and `size-audit`.

## Building vocabulary

Standard features with rough SVG conventions. New diagrams should reuse this vocabulary; new features should be added here as they're invented.

### Walls and gates

- **Compound wall** - 4-segment heavy stroke in `#2D2A24`. Draw each side as its own `<line>` so gate-openings are gaps. Don't use a single `<rect>`.
- **Main gate** - opening of ~40 px (13 ft - a grand carriage-gate's PASSAGE; the gate structure around it may be wider) in the south wall, flanked by short heavy posts (~16×14 px). Never draw the opening wider than the passage: the old 80 px opening confused structure width with passage width (size-audit, 2026-07).
- **An opening's width is the INK's, not the endpoints'** (2026-07-25; reported by `tools/pack_audit.py`'s GATE OPENINGS section). The hand-authored wall groups carry `stroke-linecap="square"`, which closes the corners cleanly but also inks half a stroke - 1.5 ft - PAST each endpoint. So writing an opening as the coordinates of its two flanking endpoints silently loses a full stroke width, 3 ft, of passage. **Pull each flanking endpoint back by half a stroke** (4.5 px on the 9 px compound wall) so the cap lands on the intended edge. All three pool manors were authored the naive way and drew every opening 3 ft narrow; on Ubame that had made the goods-cart gate WIDER than the ceremonial main gate, which is how it was finally noticed. `compound.py`'s emitter draws with butt caps and needs no correction - the trap belongs to the hand-authored idiom.
- **Threshold stone** - small cinnabar rect (~10×14, a true ~3.3×4.7 ft stone), drawn as a PAIR flanking the ROAD just outside the opening and **never in the passage** (GM 2026-07-25: a threshold stone stands ABOVE ground, so anything in the track is something a cart would have to roll over). Annotated outside the wall (e.g., "(buried Pact-Bowl checkpoint)"). This bullet used to say "centered in the gate threshold", and that wording is exactly what put Ochiba's pair INSIDE its 13.3 ft main gate with 5.3 ft of clear track between the two stones - the second round of the same defect, after a single stone drawn squarely across the passage was caught by eye in 2026-07. Now checked: `tools/pack_audit.py` `passage_blockers` keeps the whole gateway clear of furniture-scale objects, and the general form of the rule immediately caught a second instance nobody was looking for - Hayakawa's stable-yard privy standing 2 ft inside its service gate.
- **Internal divider wall** - lighter stroke (~6 px) in `#3F3A30`, separating courts, with its own gate opening.
- **Structures ABUT a wall, they never stand in it** (GM rule, 2026-07-24; checked by `tools/pack_audit.py` `structures_on_walls`). A wall is drawn at true thickness (9 px = 3 ft compound wall, 6 px = 2 ft divider) and CENTERED on the boundary it marks, so half of it lies inside the interior - and that ground belongs to the wall, not to a building. Leave **~2 ft off a compound wall and ~1.5 ft off a divider**: half the ink plus a hair, so the wall does not swallow the structure's own outline stroke. This applies to every built thing, not just the big masses - the defect that produced the rule was a 9 x 3 ft entry PORCH laid across Ochiba's court divider. Where a structure genuinely is part of the wall (a nagayamon gatehouse, a postern), draw the wall as segments **broken around it** - the idiom already used for Ochiba's kitchen postern and both south gates - so the plan states the relationship instead of quietly stacking ink. **This covers PRIVIES, sheds and well curbs too, not just the big masses** - they are built things standing on the ground. That had to be said twice: the rule already named privies in 2026-07-24, but the check's fill list did not contain the privy color until 2026-07-25, so all 23 utility rects across the pool went unchecked from the day the rule was written. Note the deliberate contrast with the occlusion check, which is fill-BLIND: nothing may legitimately bury a foreground item, so there "any later shape counts" is safe - but plenty of things legitimately occupy wall ink (gate posts flank an opening, threshold and boundary stones mark a crossing, salt wards flank a door), so a structure has to be NAMED rather than inferred from "not ground". When two checks look similar, ask whether their defaults point the same way before copying one onto the other.
- **Gatehouse** - small ~120×42 dark-wood rect just inside and BESIDE the gate opening (a guard post flanking the passage, like Takayama's monban-sho). It must never span the opening itself - a gatehouse drawn across the gate blocks the compound's front door (caught by review on both pool manors, 2026-07).
- **Threshold wards** (salt heaps, ofuda, and the like, where a subject keeps them - e.g. Hayakawa's salt wards) go on the OUTSIDE of the opening, one on EACH SIDE (a pair per entrance): the ward keeps ill fortune from crossing the threshold, so it sits outside, flanking. The postern/gate LABEL goes inside (legibility/crop), but the wards themselves stay outside - do not move them in to tighten a crop; extend the crop a few px instead.

### Outer court (administrative / public)

- **Office hall (with dais band)** - the working block (~360×84) along the north edge of the outer court, backing onto the divider wall. Rear rooms behind a dashed screen-line: the **day office** (tax and case business) and the **official study** (the magistrate's working desk). Front band on the court face: the magistrate's tatami dais centered, two clerk positions flanking. The courtroom is a room OF the office block, not a freestanding stage (see grounding).
- **Hearing court** - open sand-textured area (~360×105) immediately south of the office hall's dais band, leaving a cart-passable slot (~25-30 px) between its south edge and anything at the wall. Witness/defendant kneeling marks (~9×9 rects - a true ~3×3 ft kneeling mat; resized from the old 30×14 with the glyph-doctrine retirement) along the bottom.
- **Tax archive** - sealed-kura storehouse (~100-108 px wide, ~32-36 ft): white-plaster fill `#F2EFE4`, heavy `#4A3318` stroke, small dark door mark - visually distinct from the *vented* granary slats. It holds the ledgers (the county's tax base - fireproof walls, see grounding) AND doubles as the strongroom for tax-in-kind valuables and the coin the county holds; that combined records-plus-strongroom role is what carries it to the top of the kura range. A PURE document store trends smaller (~18-24 ft); do not push this past ~36 ft - a paper archive is not a rice kura.
- **Stables** - a small few-horse umaya (~84-96 wide × ~48-66) with vertical stall divisions. A county magistracy keeps only the magistrate's mount plus a couple of messenger/yoriki horses (~2-4), so the stable is modest - and it must be drawn SMALLER than the barracks (a stable for a handful of horses out-footing the watch's quarters was a laundered value here, ~160×80; size-audit hierarchy sweep, 2026-07).
- **Cell** - *small* (~54×60) holding structure with lattice-bar lines. Edo-style cells are small (remand-only, 1-2 occupants, a real cage ~10×12 ft); large multi-cell blocks are anachronistic for civilian magistrates. The lattice-bar LINES are linework under the stroke convention (drawn at visible stroke width); the cell FOOTPRINT is true size - the old "~2x on a side for lattice legibility" allowance is retired with the glyph doctrine (2026-07-21), and the footprint was already re-derived true (18×15 ft). Keep it well under the barracks.
- **Barracks** - moderate building (~80-160 wide) with internal bunk divisions. On-grounds barracks are well-attested even for civilian Edo administration in the countryside (rural jin'ya housed their staff in rowhouses inside the walls); it was the big urban magistracies that housed constables off-site in a district of their own. Size and occupancy follow the staff-housing knob in the magistrate's manor program below. The barracks (a ~10-20-man watch) OUT-foots the stable - if it doesn't, one of the two is wrong.
- **Granary** - raised storehouse using `granary-slats` pattern, with small stilt-blocks visible at the base. A single staging kura is ~130-150 wide × ~75-80 deep (~43-50 × 25-27 ft); a real kura is long and shallow, so keep the DEPTH near ~25 ft (the old ~135-deep box, ~45 ft, was a granary-ROW footprint the staging knob rejects; size-audit 2026-07). A terminal store (the granary-weight knob) draws a granary ROW instead of one fat box. Keep it under a residence block. Label it `granary`, not `rice granary`: contents are rice-dominant but mixed (see the grounding entry on granary contents).
- **Practice ground** - swept-earth patch (`keiko-earth` pattern - lighter than court-earth, faint broom lines - with a thin dashed border) in the outer court beside where the watch lodges (the barracks or the retainers' quarters), labeled `practice ground`. Every magistracy trains daily, but the venue is multi-use open ground, never a dedicated dojo building by default (a dojo is a city institution - see grounding; a true dojo is an Ochiba-slot particular). What makes the ground read as ESTABLISHED is the durable equipment practice leaves behind: a **weapon rack** (~8×2 ft rect) flush against the adjacent building's wall, and 1-2 **striking posts** (the kenjutsu *tategi* standing post, ~1 ft dia - NOT "makiwara", which properly names the Okinawan karate punching post / kyudo straw target; sub-glyph, so r2 location markers under the stroke convention), labeled `striking posts`. Size honestly at ~90-135 sqft per samurai actually drilling: ~1,200-2,000 sqft (a ~30-40 ft block or an equivalent strip) where the full platoon lives on-grounds (staff-housing option a), ~700-800 sqft for a duty-watch-only compound (option c). Time-sharing the ground with another yard use (cart staging, assembly muster) is period-honest; when the sharing is part of the county's story it takes an instance note (Hayakawa's bale yard). A garrison-emphasis manor may add an **azuchi** - an earthen archery target bank against a perimeter wall with a clear ~90 ft shooting lane.

### Inner court (private / sacred)

- **Residence** - the lord's family dwelling along the north range, with internal soft-divisions (dashed lines) separating rooms. Three historical rules the interior-audit added (2026-07):
  - **Mass it as offset blocks, not one bar.** Real shoin residences massed as connected offset blocks (gankō / "flying-geese" step) or an L, joined by short corridors - a single long rectangle reads as a nagaya (barracks) or honjin guest range. Draw two or three stepped blocks.
  - **Include a formal reception room** (zashiki, with the ancestral alcove/tokonoma) even when a separate office hall exists - the residence keeps a room for private-capacity guests (attested at Takayama's yakutaku). A residence of nothing but bedrooms is wrong.
  - **Only the lord's household lives here.** Occupant labels for the family's own rooms are fine as a schematic convention (they read better than okami/nakanoma/nando), but the KARO and senior retainers do NOT get bays of the lord's wing - a chief retainer of any standing kept a separate house or a compound nagaya. Draw their quarters as separate structures.
  - **Each labeled area is a multi-room ZONE, not one room** - a real residence of this footprint held ~18-25 tatami rooms; the diagram compresses each suite (reception + antechamber, the lord's rooms, the family rooms) into one labeled area for legibility. This is a tolerated simplification, so a single dashed line per block is fine, but draw an **engawa** (a thin ~8 px lighter strip, `#E8D2A8`) along the garden-facing south face of each block - the veranda is the cheap authentic marker that reads "residence," not "nagaya."
- **Entry porch (genkan)** - small projection (~40×14) from the residence's south face at the ONE formal entrance. A buke residence has a single ceremonial genkan (on the reception/zashiki block), NOT one per building; the other lodging blocks (the family block, the karo's house, a detached guest house) reach the court by an INFORMAL door - a small side/service entrance, drawn but not marked as a genkan. Every lodging block needs a drawn way in; none should read as a sealed box, and none but the reception block gets a second genkan.
- **Kitchen + pantries** - service building (~120 × ~100 = ~40×33 ft) with hearth indicator (small dark rect with a small orange circle for fire). A large institutional daidokoro (it feeds household, clerks, and the watch), but the cookhouse must be drawn SMALLER than a residence living block - a kitchen out-footing the family's own quarters is inverted (the old ~160×135, ~53×45 ft, was; size-audit 2026-07).
- **Bath house** - small detached pavilion (~36-45 px = 12-15 ft; a deliberately enlarged bath ~54×36) in the inner garden. Optional steam-plume curve above. (The old ~70-80 px standard was itself ~2× a real manor bath - size-audit, 2026-07.)
- **Inner garden** - stipple-patterned rect occupying central inner-court space. Optional ornamental pond (ellipse) and stone lanterns.

### Wells

A compound housing ~50 people plus horses needs 2-4 wells, distributed by use:

- **Kitchen well** (busiest) - small stone-curb rect (~22×22) with dark well-mouth circle, inside or immediately adjacent to the kitchen building.
- **Garden well** - same form, in the inner garden for family / ornamental use.
- **Stables well** - same form, just outside the stables for horse-watering.
- **Bath-area well** (optional fourth) - only for very large compounds; usually the kitchen well serves the bath by carry.

### Fire-water tubs

Standing fire-water (rain-fed water tubs; the Edo *tensuioke*, "heaven-water tubs") kept as first-response fire reserve. Draw as small tub glyphs (~r5 circles, water-blue `#8FB0C6` / rim `#3A5060`, distinct from the square-curb wells), DISTRIBUTED across the compound, not a token pair in one corner:

- **One tub at (the corner/entrance of) each major fire-prone WOODEN building** - office hall, residence blocks, barracks, gatehouse, shrine hall, stables, servants' quarters - so roughly 8-12 for a dozen-building compound.
- **Weight the KITCHEN heaviest** (2 tubs): the open kamado/hearth is the top ignition source, on all day.
- **Each tub sits AGAINST its building, at a wall/eaves corner** - a *tensuioke* is GUTTER-FED by roof runoff (gutter -> downspout -> tub at the wall base), so a tub standing a few feet out in the open court is fed by nothing. Place it touching the wall (its glyph ~1.7-2 ft off), never adrift in the courtyard. This is a hard geometric rule, so it is checked automatically: `tools/pack_audit.py` flags any tub more than ~3.5 ft from the nearest building ("fire-water tubs adrift"); the check has teeth (it caught both manors' tubs floating 4-14 ft out, 2026-07). It must ALSO not sit ON a well glyph - the two point-glyphs smear into one blob, and a rain-fed fire tub is not the drawing well; `pack_audit` flags a tub overlapping a well ("TUB ON WELL"). This bit a stables tub pulled to its wall at exactly the spot the stable-yard well sat (2026-07) - so when a wall is crowded by a well, move the tub to a different eaves corner.
- **A tub stands OUTSIDE the building and CLEAR of it - no part of the glyph may lie in the footprint** (GM rule 2026-07-25, tightened from "center outside" to "no overlap at all" 2026-07-26; checked by `tools/pack_audit.py` `tubs_in_buildings`, reported as TUB IN BUILDING). The two reasons are the two things the tub is for: a *tensuioke* is filled by the **downspout**, which discharges at the outside wall, and it is emptied by a **bucket line**, which forms in the open where people can reach it. A tub drawn into the footprint is fed by nothing and stands where nobody can get at it - and if the building is already burning, a water butt inside it is exactly where the water is not. So the tub's own glyph sits ~2 ft clear of the outside wall face (2.2 px is the house style on all three pool manors): far enough out to be under the eaves-line and in the open, close enough that a downspout reaches it. Note this is the COMPANION of the adrift rule, not a restatement - `fire_water_adrift` pulls a tub IN toward a building and `tubs_in_buildings` keeps it OUT of one, and only the narrow band along the outside wall satisfies both. Two validated examples, both of which the adrift check passed clean:
  - Ubame's first draft put all 19 tubs at INSIDE corners, 1.3-1.7 ft within their footprints - adjacency alone cannot tell inside from outside. Frozen as `tests/fixtures/ubame-tubs-inside-red.svg`.
  - Fixing those left ONE tub straddling a wall: the bath's tub, re-seated a correct 2.2 px off the bath's south wall, landed in the 9 px alley between the bath and karo's house - too narrow for a 7.6 px tub - so it hung 0.8 px inside the house. The center test scored it zero. **A center test has a blind band exactly the width of the glyph's radius**, and a check that measures the DRAWN DISC's penetration instead rises smoothly from the first pixel of contact, so there is no size of overlap it reads as clean. Frozen as `tests/fixtures/ubame-tub-straddle-red.svg`. The map-side lesson: when the eaves corner you want is in a narrow alley between two buildings, the tub does not fit at all - move it to a corner that faces open ground rather than splitting the difference.
- **The fireproof plaster KURA (tax archive) carries NONE** - an earthen storehouse is built precisely so it does not burn, so it is the last place the water should live. The *vented wooden granary* is a different case (it is flammable) and may take one tub as yard gap-coverage.
- Label the glyph once (`fire-water tubs`); the rest read as the same glyph.

See the "Fire discipline" grounding entry for the why.

### Latrines and the rear service strip

Very small gray rects (~14-20 px square), labeled `latrine`, away from food prep and water sources. Count and placement follow how households and night-soil actually worked (building-review sanitation sweep, 2026-07):

- **Count scales with occupancy** - roughly one privy per functional zone (residence/servants, the garrison/barracks, the administrative or stable yard), not a token one or two for the whole compound. A ~40-60-person magistracy runs ~3-4.
- **The residence privy ATTACHES to the house** - a back (north) corner, the end of an engawa/corridor - never a lone block standing out in open ground. Its cesspit faces a service edge (the rear/service wall) so an outside night-soil collector (night-soil was a valuable, carted-off commodity) reaches it without crossing the inner court.
- **Servants'/outer privies go against service walls near a gate** - by the service gate, the stable yard, or the barracks - for the same cart-access reason.

A **rear service strip** organizes all of this: the residence's formal garden sits on its SUNNY (south) side, so the shady REAR (north, between the residence and the rear wall) is the household's SERVICE zone, not empty ground. Fill it - **servants' quarters** (a nagaya; ~10 servants live on-grounds at a county manor), a kura, a kitchen/vegetable garden, the attached family privy - or, if little goes there, narrow the setback to a working service alley (~6-10 ft) hugging the wall. A wide (~20-30 ft) band of blank earth behind the residence is internal dead space, the interior counterpart of an over-loose crop (building-review internal-dead-space sweep, 2026-07).

### Sacred features

- **Modest shrine (standalone)** - small wooden structure with torii silhouette nearby (adjacent modest shrines may share one approach torii). May carry thin vermillion edging; the hall-class shrine below is distinguished by SIZE and internal altar rails, not by edging alone. For routine rural Inari shrines and the like.
- **Hall shrine (L5R-style, e.g., Fox lands)** - full building with vermillion edging (`#A03020` strips at top and bottom). Internal rail division for multiple altars; identifiers like torii silhouette (east) or straw-doll silhouette (west) for distinct altar aspects. **SIZE CEILING:** even a deliberately grand hall stays SUBORDINATE to the lord's residence - draw it at ~110×90 px (~36×30 ft) at most (a real substantial haiden is ~24-30 ft; the honden proper stays tiny, 1-3 ken). It must be ≤ ~half a residence block, and the whole sacred complex (hall + any workshop) ≤ ~2/3 of the residence. The divergence licenses a *grand hall*, not a hall that out-measures the magistrate's own house (the old 53×53 ft square did both; size-audit direction-vs-magnitude, 2026-07).
- **Workshop colonnade** - open hatched area (`colonnade-hatch` pattern) attached to a shrine's working side, for sacred craft production (e.g., cinnabar painting of threshold stones).

### Approaches and surroundings

- **Road to gate** - two stacked paths (solid translucent + dashed darker) for ~150 px into the gate from the appropriate cardinal direction, running OFF the viewBox edge. NO direction caption: every manor road leads to town and thence the Imperial road, so `to the Imperial road` / `to the town's main street` is always-true clutter - the road glyph leaving the map already says a road departs here.
- **Town / surroundings outside walls** - by default, leave the surrounding parchment empty. Only add exterior buildings if the surrounding context is itself part of the diagram's subject.

## Composition: perimeter buildings + a named court-spine

The historical Mode A layout is NOT "buildings scattered inside the walls with bare space left over." It is a **composed courtyard grammar**, and the automated checks reward composing it right - NOT minimizing empty space (a jin'ya is ~60% open BY DESIGN; see the packing grounding). This is the Mode A counterpart of the Mode B water-first layout order.

- **Office-front / residence-rear.** The compound splits into an OUTER (public/administrative) court at the gate and an INNER (private) court behind the divider wall - universal in both traditions (Chinese "front yamen, rear residence"; the Edo jin'ya office wing vs residence wing).
- **Buildings ring the edges; the center of each court is OPEN.** Service/storage buildings hug the OUTER walls of the outer court; the **office hall backs the DIVIDER** (its dais overlooking the oshirasu); the residence backs the inner court's north wall / the divider; kitchen, shrine, and retainer housing hug the inner walls. The divider is a legitimate back-wall - a building backing it is well-placed, NOT "floating" (`tools/pack_audit.py` counts the divider as a wall for perimeter-hugging).
- **The open ground is a SPINE OF NAMED COURTS, not undifferentiated slack:** the **forecourt** (marshalling apron just inside the main gate) -> the **oshirasu** (sanded hearing court before the office-hall dais) -> [divider] -> the **inner garden/court** behind the residence. Every large open region MUST be a named court/garden; an UNNAMED central void is the defect (label it or fill it), never the open ground itself.
- **So the rule inverts the naive "avoid empty space":** CENTRAL open is GOOD (courtyard - keep it, name it); a PERIMETER gap (open ground against a wall, between edge buildings) is the slack to tighten. Aim for a high **perimeter-hugging %** (most building footprint within ~one building-depth of a wall or the divider) with the court-spine held open in the center.
- **Placement order = perimeter-first (feature 008; the Mode A analog of Mode B's water-first rule):** reserve the court-spine first, then place buildings against their assigned walls in TIERS - **N/S rows first (they own the corners), then E/W columns (which flow BELOW the N/S buildings), then the divider hall last (which flows CENTERED between the E/W columns)** - each hugging its wall and sliding along it past every obstacle with fire-gaps. Within a tier, highest-`order`/largest goes first. Do NOT scatter - worst-fit bin-packing spreads buildings into the center, the opposite of the goal. (The corner rule was E/W-owns-corner through feature 007; the round-trip test of Ochiba, below, showed a residence needs to own its N corners with the kitchen flowing below, so corner ownership moved to the N/S rows and collision became real 2-D rectangle overlap.)
- **Second rank:** a building can sit as a rear rank BEHIND the wall row (tag `rank=2`), offset inward past the rank-1 row - the historical rear service strip (servants ranked behind the family wing; a privy/store behind the residence). The rank-1 row owns the wall; rank-2 flows behind it. Without this, a residence's two blocks plus a servants' row all compete for one wall and one overflows (exactly the first Ochiba round-trip failure).
- **The placer ([`compound.py`](compound.py))** encodes this as a FEET-FIRST program + perimeter-first, 2-D-collision placement: declare the envelope, the reserved court-spine, and the buildings sized IN FEET with a wall tag (`court` + `wall`, plus `order`/`rank`), and it emits a composed DRAFT SVG. Footage is the source unit; pixels are derived (3 px/ft) only at emit. Use it to START a new compound with the composition already right, then hand-refine into the final pool SVG (the placer is a scaffold, not a regenerate-every-time pipeline - the particulars, relics, and annotations are added by hand). Building masses in the program are sized to the ~37-42% coverage band (real jin'ya consolidate into a few large masses). Two worked examples: `pool/magistracies/county-magistracy-example.svg` (a generic magistracy: 38% coverage, garden/oshirasu/forecourt spine held open) and `pool/magistracies/ochiba-roundtrip-test.svg` (the **round-trip test** - the existing hand-authored Ochiba re-encoded as a program and re-placed; it reproduces the hand-composed layout: residence owning the N corners, kitchen flowing below, servants as a rear rank, office hall centered behind the oshirasu. This validated both feature-008 placer fixes and is why the live `ochiba-magistracy.svg` was left unchanged - the placer confirmed it rather than improving it).

## Checklist for a new diagram

This checklist is for **Mode A** (compound/building plans). **Mode B settlement maps** follow their own loop instead - the "Workflow (spec → validator → persona)" steps in [`settlements.md`](settlements.md): `check_village/` must report ALL CHECKS PASSED, then a persona read of the PNG. (Note the Mode B difference: title is the place name only - no subtitle/summary line. Neither mode carries a key/legend box.)

Before declaring done (Mode A):

- [ ] Subject pre-designed in conversation with the GM; scope agreed
- [ ] Sizing grounded in setting files (samurai counts, role roster, building footprints)
- [ ] Labels in English with the Japanese-reserved-for-names rule applied
- [ ] No self-evident or always-true labels: GATES/ENTRANCES carry no label (placement shows the function - kitchen entrance, service gate, river door, landing gate); no `to the road/town` direction caption; keep a label only for a genuinely non-obvious or SPECIAL feature (a threshold-stone checkpoint, not a plain gate)
- [ ] Any kanji passes the kanji ↔ romaji ↔ meaning triangle
- [ ] Title block (title + subtitle; NO redundant summary line - never restate walled / two-court / gate-south, which the plan already shows), placed just above the compound
- [ ] viewBox cropped tight to content (rectangular, ~15-25 px border; no wide empty margins); scale bar in a top corner, approach labels close to the compound, edge labels just inside their openings; any road meant to leave the map runs off the viewBox edge (not a stub stopping short)
- [ ] Scale bar present; new features sanity-checked in real feet (3 px = 1 ft)
- [ ] Every guest-facing entrance feeds a court or garden; service doors feed work areas
- [ ] Size hierarchy honest: the residence is the dominant DOMESTIC footprint (the office hall aside); kitchen < a residence living block, stable < barracks, cell < barracks, any shrine/storehouse < the residence (size-audit proportion sweep)
- [ ] Packing checked with `tools/pack_audit.py`: coverage ~37-42% (envelope NOT shrunk - it is the historical band); read the TOP-N vacant rectangles + the per-region density (a big vacant rectangle or a locally-sparse tile that is NOT the oshirasu/garden/forecourt is slack); every empty region kept as a feature carries a QUANTIFIED size (loading apron ~15-20 ft, forecourt for assembly); loose wooden service gaps abutted or tightened to ~6-8 ft fire-gaps (kura ~6-10 ft) - fragmentation fixed by consolidation, not a smaller wall
- [ ] Nothing stands in a gateway: `tools/pack_audit.py`'s PASSAGE check reports "every gateway's track is clear" (threshold stones and gate posts FLANK a passage, they never stand in it - see "Walls and gates")
- [ ] Every opening's INK width matches the width its comment claims: read `tools/pack_audit.py`'s GATE OPENINGS section figure by figure (a square cap eats 1.5 ft per end - see "Walls and gates"), and confirm the hierarchy holds with the ceremonial main gate widest
- [ ] No structure standing in a wall: `tools/pack_audit.py`'s STRUCTURE/WALL section reports "all N structures clear the wall ink" (see "Walls and gates" - buildings back a wall, porches, sheds, privies and well curbs included; a structure that IS part of the wall gets the wall broken around it)
- [ ] Privies ~one per zone (~3-4), the residence privy ATTACHED to the house; rear (north) service strip filled (servants' quarters + utility) or narrowed to an alley, not a wide empty band; every lodging block (family block, karo's house, guest house) has a drawn entrance
- [ ] Fire-water tubs (~8-12) distributed across the wooden buildings, kitchen weighted (2); each OUTSIDE its building against the wall (~2 px clear; no part of the glyph in the footprint, not even a straddle - `pack_audit` TUB IN BUILDING); NOT a token pair, and NOT at the fireproof plaster kura (fire-water sweep)
- [ ] Practice ground in the outer court beside the watch's lodging (swept patch + weapon rack + striking posts), sized to the resident platoon at ~90-135 sqft per drilling samurai; NO dojo building unless it is a recorded Ochiba-slot particular
- [ ] No key/legend box, no compass rose, no staffing box (retired conventions: the sheet is labeled directly, north-at-top is invariant, and the staffing story lives in the notes file). The only permitted boxes: the scale bar, and a short note box explaining a UNIQUE instance feature (e.g. Hayakawa's salt wards) - box prose obeys the annotation rule (instance-specific lines only, no program facts or rosters; all text fits inside its box)
- [ ] All named features visible at 2400 px render
- [ ] Self-review pass after first render (read the PNG)
- [ ] Design notes written to `pool/<subject>.notes.md` (knob settings, particulars, deliberate choices)
- [ ] `building-review` subagent pass: iterate until no findings, or remaining findings overruled with rationale recorded in the notes file's Review log
- [ ] `size-audit` subagent pass ([`/.claude/agents/size-audit.md`](../../agents/size-audit.md)): every feature checked in real feet against independently researched historical anchors - documented tolerances get RE-VERIFIED, not assumed (a wrong size once laundered itself into the docs as a tolerance). It runs [`tools/pack_audit.py`](tools/pack_audit.py) for the packing/whitespace sweep (coverage %, largest vacant rectangle, aligned building gaps)
- [ ] `.svg`, `.png`, and `.notes.md` all saved in `pool/`
- [ ] Historical-accuracy review offered to the GM at completion
